# KUE status

Lantern is the foundation KUE is being built on. This file records what exists,
measured against the KUE brief's priority order. It is updated with each
increment, and nothing is listed as REAL unless it is implemented and verified.

Labels: **REAL** · **PARTIAL** · **PLACEHOLDER** · **SIMULATED** · **NOT_IMPLEMENTED**

## Security invariants — current standing

| Invariant | Standing |
|---|---|
| Unknown data classification = DENY | **Enforced** — compile-time exhaustive match; runtime tags denied (tested) |
| Raw camera/audio cannot reach external AI | **Enforced in policy** (tested); no external path exists |
| Models cannot bypass the privacy policy | **Enforced** — the only prompt path is a sealed `Cleared<ModelPrompt>`; model output is text with no tool, command or grant path (tested) |
| Privacy policy cannot be overridden through natural language | **True** — policy is versioned code; the only runtime API (`refuse_additionally`) can only add refusals |
| Deletion removes stored data | **Enforced** for erase-all and legacy purge (raw-byte tests) |
| Secrets never appear in logs | **Policy only** — NEVER_STORE denies logs, but log output is not yet routed through the firewall |
| Kill switch stops sensing and action | **Enforced** for sensing and memory (tested, verified on device), the model process (terminated), speech (queue dropped, synthesizer process terminated, nothing accepted while killed — tested against the real process), and actions: waiting actions are cancelled, Confirm and the executor hand-off both check the kill switch (tested). An executor already running when the kill arrives is not interrupted (it finishes within its own timeout) |
| LLM cannot disable the kill switch | **Enforced** — recovery requires `Principal::Owner`; model/automation/external refused (tested); no model has a path to the recovery commands |
| Unknown authorization = DENY | **Enforced** — unknown operation tags denied; exhaustive requirement table (tested) |
| Unknown identity cannot become authorized | **Enforced** — UNKNOWN_PERSON / MULTIPLE_PEOPLE lock and revoke; Touch ID cannot override (tested) |
| LLM cannot grant itself permission | **Enforced** — grants come only from a LocalAuthentication SUCCESS; MODEL cannot request owner operations or cause prompts (tested, mutation-checked) |
| Unknown action = DENY | **Enforced** — closed enum + deterministic parser; no generic command path (tested) |
| Every reported success has verification evidence | **Enforced** — `ActionRecord::finish` downgrades an unverified SUCCEEDED to UNKNOWN_RESULT (tested) |
| No simulated capability represented as real | **Held** — capability panel lists every signal with its status; claim phrases may only sit on rows KUE does not have, which is a test |
| KUE acts only on what it found and showed you | **Enforced** for file moves — a path absent from the last storage report is refused before authorization (tested, including the copy KUE itself decided to keep) |
| Nothing KUE does is irreversible | **Held** for files — the only file-removing action is a move to the Trash, undoable from the recorded location; no delete verb exists in the executor |
| Every transmitted data item passes privacy policy | **Enforced for memory, model prompts and the action path** — sealed clearances at each (tested); the KueAct hand-off is contained (target on stdin, not in argv) but is not a firewall destination; stderr is not routed through policy |

## Naming

The repository and app are still named Lantern (bundle id `dev.lantern.desktop`).
Renaming to KUE changes the bundle identity, which resets the macOS camera
permission, so it is deferred to a deliberate step rather than done in passing.
What each name would break, and the order to rename in, is in
[KUE_RENAME_PLAN.md](KUE_RENAME_PLAN.md).
